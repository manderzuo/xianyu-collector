# 闲鱼管理系统商用交付与迁移实施计划

## 目标

将项目交付方式从“复制源码目录、依赖 Docker 在线构建”升级为可恢复、可升级、可迁移的商用交付体系：

- 新电脑首次安装使用离线镜像包，不依赖 Docker Hub、GitHub 或代理下载业务镜像。
- 后续启动自动检查版本，使用腾讯云作为唯一客户端更新源。
- 更新按服务只拉取变化的镜像归档，清单和归档均校验签名/哈希，失败自动回滚。
- 桌面启动、安装、更新和诊断最终由 GUI EXE 完成，命令行脚本仅作为内部实现和故障兜底。
- 更换腾讯云服务器时，用户、权限、邀请码、闲鱼账号、会话和业务文件可以一次性恢复。
- 服务器扩容时，入口域名、客户端更新地址和数据隔离规则保持不变。

## 当前基线

当前仓库仍保留兼容入口：

- `tools/windows-installer-*.ps1` 负责本地 Docker 安装、启动、停止和诊断。
- `tools/build-windows-installer.ps1` 生成可复制的便携安装目录。
- GitHub Actions 构建并推送业务镜像，腾讯云保存更新清单。
- 数据保存在 Docker named volumes；云端认证服务数据位于服务器独立目录。

当前阶段不删除旧入口、不覆盖用户数据。新能力通过新参数和新目录逐步接入。

## 交付架构

```text
开发/发布
  └─ GitHub 私有仓库（代码、审计、备份）
       └─ 发布到腾讯云
           ├─ HTTPS 更新清单和安装包
           ├─ 镜像压缩归档和 SHA-256 校验
           ├─ 云端注册审批服务
           └─ 备份与迁移包存储

客户端
  └─ GUI 启动器
      ├─ 本地离线镜像导入
      ├─ 启动和健康检查
       ├─ 签名清单、增量归档更新与回滚
      └─ 日志导出

服务器迁移
  └─ 加密迁移包
      ├─ 数据库逻辑备份
      ├─ Redis 快照
      ├─ named volumes 中的业务文件
      ├─ 云端认证数据库和密钥
      └─ Compose/Nginx/版本配置
```

## 实施阶段

### 阶段一：离线安装和迁移基础（当前开始）

- 增加离线镜像包构建工具和校验清单。
- 安装程序检测并导入离线镜像；镜像齐全时跳过 Docker Hub 拉取和本地构建。
- 增加服务器迁移导出、导入和健康检查脚本。
- 迁移包使用密码加密，默认不覆盖已有目标数据。
- 发布清单扩展为可记录安装包、校验值和最低启动器版本。

### 阶段二：腾讯云发布源

- 使用现有腾讯云 Nginx HTTPS 站点托管 `latest.json` 和客户端维护包，并在同一域名 `/v2/`
  提供只读 Docker Registry，不增加 TCR 费用。
- GitHub 负责构建镜像并通过 SSH 导入腾讯云 Registry；客户电脑不访问 GitHub/GHCR，只访问腾讯云域名。
- 首次安装包保留完整镜像；后续发布自动以上一个线上稳定版本为父层，`docker pull` 按内容摘要复用本机已有层。跨版本客户端会直接下载缺少的中间层，无需逐版执行更新。
- 首个增量版本从腾讯云的 1.0.10 离线基线构建；后续构建从 GHCR 中的上一稳定版本读取同一层链，避免每次重复占用腾讯云低带宽出口。每经过若干版本或层链明显膨胀时，再制作新的完整离线基线。
- Registry 公网入口只允许 `GET`/`HEAD`，写操作只能在服务器回环地址完成，客户端不保存仓库密码。
- 发布流程先导入全部镜像并验证 Registry，再最后替换 `latest.json`，避免客户端看到不完整版本。
- Registry 数据目录纳入服务器迁移包；旧镜像清理由显式维护操作执行，禁止更新流程删除数据。

### 阶段三：自动更新和回滚

- 每次启动先启动本地健康版本，再后台检查更新，不阻塞网页打开。
- 下载升级包后校验 SHA-256；清单使用 RSA-SHA256 detached signature，正式发布工作流缺少私钥时直接失败。
- 客户端维护包先校验并暂存，下一次启动时替换 GUI/维护脚本，避免更新进程覆盖自身。
- Docker 镜像拉取和数据库迁移成功后才写入当前版本标记。
- 新版本健康检查失败时自动切回旧版本，并保留完整日志。

### 阶段四：GUI 安装器和启动器

- 使用自包含 Windows GUI EXE 替换用户可见的 BAT 入口。
- 安装路径由用户选择，不写死盘符。
- 支持 Docker/WSL 检查、离线镜像导入、安装进度、更新进度和诊断导出。
- 桌面快捷方式直接指向启动器 EXE，不再经过多层 PowerShell `Start-Process`。
- 保留脚本入口用于维护和兼容旧安装。

### 阶段五：热更新和扩容

- 前端/API 使用蓝绿切换，WebSocket 支持连接排空和自动重连。
- Scheduler 使用主节点锁，防止扩容或更新时重复执行任务。
- 数据库迁移采用向前/向后兼容的 expand/contract 方式。
- 先支持单服务器纵向扩容，再支持 API/WebSocket 多副本和独立数据库/对象存储。

### 通知通道专项

- 当前后端已经提供飞书、企业微信、钉钉、通用 Webhook、Bark、Telegram、PushPlus 和 SMTP
  的配置及测试发送接口；通知渠道按当前平台用户保存，不绑定到某个闲鱼账号。
- QQ 目前保留为联系/二维码信息，不把个人 QQ 号误当成机器人推送通道；如要接入 QQ 机器人，
  单独按机器人供应商的 HTTPS Webhook 协议接入，不在客户端保存平台登录密码。
- 商用上线前逐个渠道执行真实测试，校验超时、第三方返回码、重试、限流和敏感信息脱敏；
  未完成实测的通道不在产品页标记为“已畅通”。

### 客户端错误日志专项

- 安装器、启动器、更新器或停止器失败时，GUI 保留 PowerShell 的实际输出，不再只显示退出码；
  同时写入客户端 `app\logs\launcher-error.log`，方便用户复制或打开日志目录。
- 用户点击“上传诊断日志”后，客户端只生成脱敏 ZIP：包含版本、构建号、系统环境、Docker 状态、
  最近服务日志和安装器错误日志；`.env` 只按白名单取非敏感配置，密码、Token、Cookie、Authorization
  等字段在上传前统一替换为 `[REDACTED]`。
- 上传入口允许未登录设备提交安装故障，但不接受客户端传入的用户归属；已登录上传由云端会话推导
  `owner_user_id`。服务端保存加密归档，默认保留 30 天、单包不超过 10MB、总量不超过 512MB，
  并对匿名/已登录设备分别限流。
- 主平台管理员页面新增“客户端错误日志”，支持 15 秒刷新、状态/级别筛选、详情、下载、标记已解决
  和删除；云端独立审批页同步提供同一组查看与下载能力。管理员只能通过云端登录会话操作。

## 服务器迁移规则

迁移前旧服务器继续保留，只有新服务器通过健康检查和业务验收后才切换 DNS。迁移工具不复制运行中的容器进程，而是恢复可重建状态：

- MySQL 使用一致性逻辑备份。
- Redis 使用快照；缓存失效时允许重建。
- `static-files`、`backup-files`、`browser_data` 等业务文件单独归档。
- 云端认证服务的 SQLite 数据库、会话密钥和 systemd 配置单独归档。
- Nginx 配置和证书作为迁移项保存，恢复时先测试配置再 reload。
- `.env` 和其他密钥只进入加密迁移包，不出现在日志和普通诊断报告中。

迁移成功后客户端仍使用原域名。只有 DNS 指向改变，客户端不需要重新安装、重新登录或重新绑定账号。

## 安全要求

- 客户端只访问腾讯云 HTTPS 443 入口。
- Docker Registry 公网写入必须禁止；本机导入通过 SSH 完成，客户端拉取使用 HTTPS 和镜像层摘要校验。
- 更新清单使用 RSA-SHA256 detached signature，镜像归档验证 SHA-256；缺少签名时拒绝商业包更新。
- 迁移包采用密码加密，密码不通过命令行参数和日志传递。
- 恢复前自动生成目标服务器备份；覆盖动作必须显式确认。
- 保留用户和闲鱼账号的归属字段，迁移不改变 `owner_id` 等隔离关系。

## 验收标准

- 全新电脑使用离线包可以在无 Docker Hub 网络时完成镜像导入和启动。
- 已安装电脑启动时自动检查更新，更新失败仍能打开当前版本。
- 普通代码更新只下载变化的镜像层，已存在的 Python、Chromium、Playwright 等层不重复下载。
- 更新失败可以恢复上一版本，数据库和用户数据不丢失。
- 新服务器恢复后注册、审批、登录、账号同步和云端认证可用。
- 服务器更换后旧客户端不改配置仍能运行和更新。
- 诊断窗口不会闪退，日志可以复制和导出。
