# 闲鱼自动化运营系统

## 项目介绍与完整操作手册

**文档版本：** V1.0  
**编写日期：** 2026-09-06  
**适用对象：** 系统管理员、运营人员、普通用户、部署维护人员  
**文档性质：** 项目介绍、功能说明、日常操作、异常处理、运维参考

---

## 一、项目概述

### 1.1 项目定位

本系统是一套面向闲鱼店铺和多账号运营场景的综合管理系统，重点解决以下问题：

- 多个闲鱼账号统一接入、统一查看和统一维护。
- 商品、素材、地址、订单、卡券和自动回复集中管理。
- 通过真实闲鱼登录态执行商品同步、消息处理、订单处理、发布和监控。
- 通过定时任务完成账号续期、消息同步、订单同步、自动回复、商品监控和数据汇总。
- 通过角色、套餐、功能开关和配额实现平台化运营及客户分级。
- 通过数据总览向运营人员或客户展示经营指标。

系统不是单纯的页面展示工具。账号、商品、订单、消息、日志和任务均以数据库中的真实记录为基础；需要闲鱼账号或第三方服务授权的动作，在未配置或授权失效时会记录明确的失败、待配置或需要人工处理状态，不把未完成的外部动作伪装成成功。

### 1.2 适用业务

系统适合以下业务模式：

1. 一个运营主体管理多个闲鱼账号。
2. 多个客户分别登录平台，客户之间的数据和闲鱼账号相互隔离。
3. 数字商品、服务类商品或卡券类商品的自动发货。
4. 通过关键词、商品规则或 AI 为买家自动回复。
5. 对商品进行采集、选品、价格监控和分销管理。
6. 为客户提供经营数据大屏和账号经营分析。

### 1.3 核心价值

| 价值方向 | 系统能力 |
| --- | --- |
| 多账号 | 扫码登录、密码登录、Cookie 接入、状态管理、代理设置、批量操作 |
| 提效 | 自动回复、自动发货、订单同步、自动评价、自动求小红花、定时擦亮 |
| 运营 | 商品管理、发布、采集、监控、分销、卡券和消息通知 |
| 数据 | 仪表盘、数据总览、趋势指标、流量分布、商品分布、账号轮播展示 |
| 平台化 | 用户、角色、套餐权限、配额、邀请码、公告、广告、审计日志 |
| 稳定性 | WebSocket 长连接、自动重连、Cookie/Token 续期、任务运行记录、健康巡检 |

### 1.4 系统边界

系统负责平台内部的配置、数据保存、调度和动作编排。下列动作最终仍受闲鱼账号本身的登录态、平台权限、风控策略和第三方服务状态影响：

- 闲鱼扫码最终确认、人脸核验。
- 闲鱼真实商品发布、擦亮、发货、评价和消息发送。
- 邮件、支付、卡券上游等外部服务。
- 闲鱼数据罗盘中平台没有返回的画像维度，例如来源和地域。

出现上述情况时，应以页面提示、业务日志和对应账号状态为准。

## 二、系统架构与运行组成

### 2.1 服务组成

| 服务 | 作用 | 默认容器端口 |
| --- | --- | ---: |
| Frontend | Web 管理界面，负责页面展示和用户操作 | 由 Nginx 或前端开发服务器提供 |
| Backend | 鉴权、业务 API、数据库读写、文件上传和业务编排 | 8089 |
| WebSocket | 闲鱼消息长连接、心跳、在线状态、实时消息和重连 | 8090 |
| Scheduler | APScheduler 定时任务服务 | 8091 |
| MySQL | 用户、账号、商品、订单、日志和配置数据 | 3306 |
| Redis | 缓存、会话辅助数据、任务和实时通信辅助数据 | 6379 |

技术栈为 Python 3.11、FastAPI、SQLAlchemy、MySQL、Redis、APScheduler、React、TypeScript、Vite、TailwindCSS 和 Zustand。发布或验证场景会使用 Playwright/Patchright；接口型动作优先使用闲鱼 mtop 直连。

### 2.2 数据流简图

```text
用户浏览器
   │
   ├── Frontend：页面、表单、图表、实时刷新
   │       │
   │       ├── Backend API：鉴权、业务、权限、数据库
   │       ├── WebSocket：消息、在线状态、重连
   │       └── Scheduler：定时执行、续期、同步、监控
   │
   ├── MySQL：业务持久化
   ├── Redis：缓存与协调
   └── 闲鱼及外部服务：真实登录态和外部动作
```

### 2.3 端口和隔离原则

生产环境、稳定旧环境和预览环境必须使用不同的端口、容器名称、Compose 项目或独立网络。

特别注意：**19000 是既有稳定旧端口时，任何新版本验证都不得覆盖、重建或映射到 19000。** 新版本应使用另一个明确的新端口，并确认新端口背后的前端、后端、WebSocket 和调度器连接的是同一套预览服务。

## 三、角色、账号和数据隔离

### 3.1 平台用户角色

| 角色 | 主要权限 |
| --- | --- |
| 管理员 ADMIN | 管理用户、套餐、配额、邀请码、系统设置、公告、广告、定时任务、全局日志和全局账号 |
| 运营人员 OPERATOR | 执行业务运营操作，具体可见菜单和功能由平台配置决定 |
| 普通用户 MEMBER | 仅查看和操作本人名下的闲鱼账号及本人业务数据，不能进入管理员功能 |

角色权限之外，还会叠加套餐功能开关和配额限制。即使页面存在某个入口，用户没有对应功能授权时，系统也应以“未开通套餐功能”或“以上属于 VIP 内容”提示，并阻止实际执行。

### 3.2 两类账号的区别

系统中有两类容易混淆的账号：

1. **平台账号**：用户登录本系统使用的账号，例如 admin 或普通客户账号。
2. **闲鱼账号**：通过扫码、密码或 Cookie 接入的实际闲鱼店铺账号。

一个平台账号可以绑定多个闲鱼账号。平台账号是数据隔离和权限计算的主体；闲鱼账号是实际执行闲鱼动作的主体。

### 3.3 数据隔离规则

- 普通用户只能读取、修改和删除自己名下的闲鱼账号及业务数据。
- 管理员可以查看平台范围内的数据，但执行具体账号动作时仍应确认目标账号。
- 不同平台用户之间的商品、订单、消息、卡券、关键词、日志和数据分析不应互相显示。
- AI 自动回复配置属于平台账号配置，同一个平台账号下的所有闲鱼账号共享；它不是单独绑定某一个闲鱼账号。
- 导入、批量操作和定时任务都必须在当前用户权限范围内执行。

### 3.4 状态含义

| 状态 | 含义 | 处理建议 |
| --- | --- | --- |
| 启用/active | 允许任务和业务动作使用该闲鱼账号 | 仍需确认 Cookie 和在线连接有效 |
| 禁用/inactive | 被人工或业务配置停用 | 检查账号管理中的禁用原因，确认后手动启用 |
| 过期/expired | 登录态失效或续期失败后的业务状态 | 查看续期日志，必要时重新扫码 |
| 暂停/paused | 暂时不执行部分账号动作 | 检查暂停时长和账号设置 |
| 在线 | WebSocket 或账号连接处于可用状态 | 可接收实时消息，仍需以闲鱼接口响应为准 |
| 离线 | 没有有效长连接或连接已断开 | 检查 Cookie、WebSocket、网络和自动重连 |

“禁用”和“离线”不是一回事；“过期”也不等同于管理员手动禁用。排查时必须同时看启用状态、登录态、在线状态和最近错误。

## 四、首次使用流程

### 4.1 管理员首次登录

首次部署后使用管理员账号登录并立即修改密码。生产环境不得在页面展示默认账号信息。

首次登录建议按以下顺序操作：

1. 登录平台。
2. 进入“个人设置”修改密码。
3. 进入“系统设置”检查运行环境、Token 获取方式、品牌、通知和菜单配置。
4. 在“用户管理”检查默认用户、角色、套餐和账号上限。
5. 在“套餐与功能权限”配置功能开关、配额和无限制项。
6. 在“账号管理”添加一个测试闲鱼账号。
7. 同步该账号商品，发送一条测试消息，确认 WebSocket 和自动回复链路。
8. 进入“定时任务”确认任务加载、调度器状态和最近运行记录。

### 4.2 普通用户首次使用

1. 使用管理员发放的邀请码注册，或使用管理员创建的账号登录。
2. 完善个人设置并确认当前套餐、到期时间和账号数量配额。
3. 添加自己的闲鱼账号。
4. 先确认账号显示为启用，再确认在线状态。
5. 同步商品后再配置商品回复、卡券和发布任务。
6. 通过在线聊天或消息日志验证实时连接。

### 4.3 页面通用操作

- 页面首次进入会加载数据；已有内容刷新时尽量保留原内容，只更新发生变化的数字或状态，减少整页闪烁。
- 页面上的“刷新”只刷新当前模块；实时模块会按主题自动刷新。
- 遇到权限不足、配额耗尽或 VIP 功能，按照弹窗提示处理，不要反复点击造成重复任务。
- 批量操作前先筛选账号，确认数量和账号归属，再执行。
- 重要动作执行后优先查看成功提示、业务日志和目标数据是否已变化。

## 五、账号管理

入口：**账号管理**。

### 5.1 添加闲鱼账号

系统支持扫码登录、账号密码登录和手动输入 Cookie 三种方式。

#### 方式 A：扫码登录

1. 点击“添加账号”。
2. 选择“扫码登录”。
3. 使用闲鱼 APP 扫描页面二维码。
4. 按页面提示完成确认或人脸验证。
5. 登录成功后系统创建或更新闲鱼账号，并保存登录态。
6. 返回账号列表，确认账号 ID、备注、启用状态和在线状态。

二维码一般有有效期。二维码已经过期时点击“刷新二维码”，不要继续使用旧二维码。

如果普通用户没有扫码登录权限，二维码从生成前就应被拦截并提示 VIP；如果对应次数或配额已经用完，再次点击也应出现 VIP 提示，而不是显示一个无法完成的二维码流程。

#### 方式 B：账号密码

1. 选择“账号密码登录”。
2. 填写闲鱼账号或手机号和密码。
3. 点击登录并按提示处理人脸验证。
4. 等待登录状态变为成功。

密码登录不是所有账号都适用，且可能触发人脸验证、风控或平台额外校验。密码只用于登录流程，不要在聊天、日志或截图中传播。

#### 方式 C：手动输入 Cookie

1. 选择“手动输入 Cookie”。
2. 填写账号标识。
3. 粘贴完整 Cookie。
4. 提交后返回账号列表。
5. 建议立即补充账号密码（如允许），用于后续自动续期兜底。

Cookie 属于敏感登录凭证。不要把 Cookie 发给他人，不要提交到代码仓库，不要在公开截图中展示。

### 5.2 账号启用、禁用与批量操作

账号列表支持单个或批量启用、禁用、关闭通知、清除 Token 缓存、账号续期和补评价等操作。

执行批量操作前：

1. 使用状态、在线状态、账号 ID 或归属用户筛选。
2. 核对已选择数量。
3. 确认动作名称和目标账号。
4. 执行后查看成功数量、失败数量和失败原因。

不要把“离线”直接当作“禁用”。如果账号状态显示过期，应优先查看登录续期日志；如果启用但离线，应检查 WebSocket 和登录态。

### 5.3 账号编辑和运营开关

账号详情可配置或查看：

- 账号备注、账号 ID、Cookie、账号密码。
- 是否启用。
- 代理地址和端口。
- 默认回复。
- AI 回复开关。
- 定时补发货。
- 定时补评价。
- 商品擦亮。
- 自动确认发货。
- 卡券发送与确认发货顺序。
- 已下单用户是否禁止 AI 回复。
- 消息合并等待时间和自动回复延迟。
- 人脸验证记录、确认收货后的自动消息和自动评价配置。

### 5.4 自动续期和自动重连

系统包含 Cookie 续期、Token 续期、WebSocket 心跳和断线重连机制。正常情况下：

- Cookie 续期任务按调度器周期运行。
- Token 续期任务按调度器周期运行。
- 长连接断开后尝试自动重连。
- 业务动作成功返回的新 Cookie 会被保存，供后续签名和续期使用。

自动续期不是“永远不需要扫码”。以下情况仍可能需要人工重新扫码：

- 闲鱼服务端撤销了全部登录态。
- 浏览器续期环境失效或被风控拦截。
- 账号没有可用的账号密码兜底。
- Token、Cookie 已过期且接口续期无法取得新的长期登录态。
- 代理、网络或外部接口不可用。

排查路径：

1. 账号管理确认账号是否启用、是否过期、是否有 Cookie。
2. 查看“登录续期日志”“Token 续期日志”“COOKIES 刷新日志”“接口续期 Cookies 日志”。
3. 查看最近失败原因，不要只看“离线”两个字。
4. 检查账号是否配置密码、浏览器数据目录是否可用、代理是否正常。
5. 需要人工操作时重新扫码，成功后再次观察自动重连和任务日志。

## 六、消息、在线聊天与自动回复

### 6.1 在线聊天

入口：**在线聊天**。

在线聊天依赖有效的闲鱼登录态和 WebSocket 长连接。可用于：

- 查看会话和历史消息。
- 查看买家消息。
- 发送文字消息。
- 发送图片消息（如果账号和接口允许）。
- 撤回消息（以平台权限为准）。
- 使用快捷短语。

如果所有账号同时离线，应先检查 WebSocket 服务和账号登录态；如果只有一个账号离线，优先检查该账号 Cookie、代理和风控状态。

### 6.2 AI 自动回复的正确归属

AI 自动回复配置绑定的是**平台账号**，不是某一个闲鱼账号。

操作步骤：

1. 进入账号管理或 AI 回复设置入口。
2. 确认当前登录的平台账号。
3. 填写 API 提供商、Base URL、API Key、模型和系统提示词。
4. 保存配置。
5. 点击“测试 AI 连接”，确认返回成功。
6. 在需要使用 AI 的闲鱼账号上开启 AI 回复开关。

保存一次平台账号配置后，该平台账号名下的所有闲鱼账号可以共享这套 AI 配置。闲鱼账号上的开关只控制该账号是否实际启用 AI 回复，不会复制出多套 API 配置。

### 6.3 回复优先级和规则建议

建议按以下顺序配置：

1. 消息过滤和黑名单先行，避免不应回复的内容进入自动化链路。
2. 商品专属回复处理明确的商品问题。
3. 关键词回复处理固定问法。
4. AI 回复处理开放式咨询。
5. 默认回复作为兜底。

配置后至少用买家测试账号验证：

- 命中关键词时是否回复正确内容。
- 未命中关键词时是否进入 AI 或默认回复。
- 已下单用户是否按设置停止 AI 回复。
- 图片、卡券和延迟是否符合预期。
- 消息日志是否记录触发规则、回复结果和失败原因。

## 七、商品管理与商品发布

### 7.1 商品管理

入口：**商品管理**。

首次接入闲鱼账号后，建议点击“同步商品”，将闲鱼侧的商品快照拉入系统。同步后可查看：

- 商品名称、商品 ID、价格和状态。
- 商品所属闲鱼账号。
- 默认回复。
- AI 提示词。
- 自动发货配置。
- 多规格发货开关。
- 多数量发货开关。

添加商品或发布商品后，系统会尝试同步并刷新本地商品数据。如果页面暂时没有显示，先点击商品管理中的刷新或同步，并查看发布日志、同步状态和最近错误。

### 7.2 素材库和地址库

入口：**商品发布 → 素材库**、**商品发布 → 地址库**。

素材库用于统一维护发布图片、商品介绍和可复用内容。地址库用于保存发货或商品所在地信息。上传前检查文件格式、大小和内容，避免重复素材或包含敏感信息。

### 7.3 单品发布

入口：**商品发布 → 单品发布**。

建议流程：

1. 选择目标闲鱼账号。
2. 选择或上传商品图片。
3. 填写商品标题、描述、价格、库存和分类。
4. 选择地址或商品所在地。
5. 配置规格、发货方式和服务信息。
6. 执行平台账号能力检测。
7. 提交发布。
8. 查看发布结果和发布日志。
9. 返回商品管理确认商品已同步。

服务类商品可能先生成草稿，再提示扫码在闲鱼 APP 完成服务信息和库存发布。这表示平台动作需要真实闲鱼端确认，不代表后台已经完成最终发布。遇到再次扫码，应按发布日志中的阶段和失败原因判断是登录态确认、服务商品确认还是平台风控。

### 7.4 批量发布

入口：**商品发布 → 批量发布**。

批量发布前应先用一个账号、一个商品完成单品验证，再进行批量操作。操作时：

1. 选择商品数据或导入任务。
2. 选择目标账号范围。
3. 检查图片、分类、库存和价格。
4. 确认配额和发布数量。
5. 提交批量任务。
6. 在发布日志中查看每个账号、每个商品的结果。

平台风控、账号权限、图片失败或地址失败可能导致部分成功、部分失败，应按明细逐项处理，不要无条件重复全部任务。

### 7.5 发布日志

发布日志用于确认：

- 任务创建时间、目标账号和商品。
- 当前阶段：草稿、提交、等待确认、成功或失败。
- 平台返回的原始原因。
- 是否需要扫码或人脸验证。
- 重试次数和最近执行时间。

真实发布、擦亮和验证动作都必须以平台响应和日志为准。

## 八、卡券、订单与售后

### 8.1 卡券管理

入口：**卡券管理**。

系统支持固定文字、批量数据、API 内容和图片等卡券类型，具体可用能力由套餐、账号和上游服务决定。

入口：**订单管理**。

- 查看订单详情。
- 手动发货。
- 自动发货。
- 查看卡券发送记录。
- 查看发货、退款和超时状态。

### 8.3 自动发货与售后

- 账号在线或具备有效接口登录态。

- 账号已开启相应自动确认或发货设置。

系统还支持定时补发货、发货超时检测、退款超时检测、确认收货后的消息和自动评价。出现失败时，查看对应批次日志，不要直接手动重复发货。

## 十四、常见问题处理

### 14.1 登录失败，请检查网络连接

检查顺序：

1. 浏览器是否能访问当前前端地址。
2. 前端配置的 Backend URL 是否正确。
3. Backend `/health` 是否正常。
4. 浏览器开发者工具 Network 中 API 是否返回 401、403、404 或 5xx。
5. 用户是否被停用、封禁或已到期。
6. JWT、跨域或反向代理配置是否异常。

### 14.2 二维码已扫描，一直等待确认

可能原因：闲鱼端尚未最终确认、人脸验证未完成、登录会话已过期或平台风控拦截。普通用户没有扫码权益时，应在二维码生成前由权限系统阻止并弹出 VIP 提示；不能让用户走完扫码后才发现无权限。

处理方式：关闭当前会话，重新生成二维码；如果仍然重复，查看账号登录日志和系统日志，确认当前套餐、配额和平台返回原因。

### 14.3 账号自动变成禁用或两个账号都离线

先区分三件事：

- 账号是否被人工禁用。
- 登录态是否 expired。
- WebSocket 是否 offline。

查看账号详情、最近禁用原因、续期批次和 WebSocket 日志。多个账号同时离线通常优先排查 WebSocket、网络或公共配置；单个账号离线通常优先排查该账号 Cookie、代理和平台风控。

### 14.4 自动续期没有生效

自动续期只能在至少一种续期条件满足时成功。确认账号是否有有效 Cookie、浏览器数据是否完整、是否配置账号密码、续期任务是否启用、代理是否可用。若平台撤销全部登录态且没有密码或持久浏览器会话，仍需重新扫码绑定。

### 14.5 服务类商品又要求扫码

服务类商品发布可能分为草稿生成、服务信息确认、库存发布和最终提交多个阶段。后台提示扫码通常表示需要在闲鱼 APP 完成真实确认，不等同于普通登录二维码。查看发布日志中的任务阶段和平台原始原因。

### 14.6 数据总览显示暂无数据

检查：

1. 当前闲鱼账号是否已选择。
2. Cookie 是否有效。
3. 账号是否开通或具备卖家数据权限。
4. 日期范围是否正确。
5. 是否已经执行过商品、订单和数据同步。
6. 数据罗盘接口是否返回数据。

来源和地域没有有效数据时，线上可以隐藏这两个模块；接口保留，不影响其他指标。

### 14.7 商品添加后看不到

商品数据通常需要完成一次同步才会进入商品管理。本系统在发布或添加商品后会尝试同步；如果仍未显示，手动点击同步/刷新，确认目标账号、商品 ID、发布日志和同步错误。

### 14.8 AI 配置后只有一个闲鱼账号能用

确认配置入口保存的是当前平台账号的 AI 配置，而不是旧的闲鱼账号级配置。然后检查其他闲鱼账号是否打开 AI 回复开关、是否在同一个平台账号名下，以及套餐是否允许 AI 功能。

### 14.9 普通用户可以看到别人的闲鱼账号

立即停止继续操作，记录平台账号、闲鱼账号 ID 和请求时间。检查数据接口是否使用当前用户过滤条件、前端是否错误缓存了旧列表、管理员测试账号是否仍在同一浏览器会话。修复后清理浏览器缓存并重新登录验证隔离。

## 十五、部署与维护参考

### 15.1 本地或隔离环境启动

```bash
cp .env.example .env
docker compose up -d --build
```

健康检查：

```text
http://127.0.0.1:8089/health
http://127.0.0.1:8090/health
http://127.0.0.1:8091/health
```

前端开发服务器通常使用 9000，打包预览可使用 9001。生产部署应使用独立域名或反向代理，并将 Frontend、Backend、WebSocket 和 Scheduler 的地址对应到同一套环境。

### 15.2 新版本预览环境

预览环境必须做到：

- 使用新的前端访问端口。
- 使用新的后端、WebSocket 和 Scheduler 映射端口。
- 使用独立容器名称或 Compose 项目名。
- 明确是否共用 MySQL、Redis、静态文件和浏览器数据目录。
- 预览服务不得映射到旧稳定端口 19000。
- 验证完成前不要停止旧稳定服务。

### 15.3 备份和恢复

管理员可查看数据库备份日志。维护建议：

1. 每天检查数据库备份任务是否成功。
2. 定期将备份复制到独立存储。
3. 恢复前先停止写入或切换到维护模式。
4. 恢复前确认备份时间、数据库和目标环境。
5. 恢复后验证用户、闲鱼账号、商品、订单和任务表。

备份文件和 Cookie 同样属于敏感数据，应限制访问权限。

### 15.4 生产安全清单

- 修改默认管理员密码。
- 生产环境关闭开发免登录。
- 修改 JWT_SECRET、数据库密码和 Redis 密码。
- 限制 Backend、WebSocket、Scheduler 端口的公网访问。
- 使用 HTTPS。
- 不在日志中打印完整 Cookie、密码和 API Key。
- 为不同客户使用独立平台账号。
- 变更前备份数据库，变更后检查健康状态。
- 旧稳定端口和预览端口严格隔离。
- 对真实闲鱼账号操作设置最小权限和人工复核。

## 十七、术语表

## 十八、交付验收标准

系统交付或新版本上线前，至少完成以下验收：

1. 管理员和普通用户可以正常登录，角色菜单符合预期。
2. 普通用户看不到其他平台用户的闲鱼账号、商品、订单和消息。
3. 扫码、密码或 Cookie 至少有一种方式可以接入测试账号。
4. 测试账号可以同步商品并显示商品名称。
5. 在线聊天能够建立连接，断线后有自动重连行为。
6. AI 配置保存到平台账号后，同平台账号下多个闲鱼账号可以共享。
7. 套餐未授权或配额耗尽时，从二维码或动作入口前置拦截并提示 VIP。
8. 单品发布、批量发布和发布日志状态一致。
9. 订单同步、卡券发货和失败日志可追踪。
10. 数据总览的四项核心指标和账号轮播工作正常。
11. 流量分布跟随顶部账号和日期，不需要二次选择。
12. 来源和地域无数据时不展示空模块，但接口仍保留。
13. 定时任务列表可以加载、手动执行并记录结果。
14. Cookie 续期、Token 续期、消息同步和健康巡检任务正常。
15. 新版本使用独立端口，未影响 19000 旧稳定端口。
16. 数据库备份和敏感信息保护符合生产要求。

## 十九、对外项目介绍（可用于官网、方案书或客户演示）

### 闲鱼多账号智能运营平台

闲鱼多账号智能运营平台，面向数字商品、服务商品和店铺运营团队，提供从账号接入、商品发布、自动回复、订单处理到经营数据分析的一体化管理能力。

平台支持多个闲鱼账号统一管理，同时通过平台用户、角色、套餐权限和数据隔离机制，为不同客户提供独立、可控的运营空间。运营人员可以在一个后台完成商品素材维护、单品及批量发布、订单同步、卡券自动发货、关键词回复、AI 智能回复、商品采集、选品监控和分销管理。

系统通过 WebSocket 实时连接、账号登录态续期、断线自动重连和定时任务中心，降低人工重复操作，提升多账号运营的稳定性。数据总览以支付笔数、支付金额、咨询人数、在架商品数等核心指标为中心，支持趋势查看、账号轮播和客户展示。

平台坚持真实链路原则：需要闲鱼账号授权或第三方配置的业务，均以真实登录态、平台返回结果和执行日志为准；当授权失效、能力未配置或平台拒绝动作时，系统会明确提示并保留可追踪记录。

### 适合谁使用

- 闲鱼数字商品和卡券商家。
- 多闲鱼账号运营团队。
- 需要自动回复和自动发货的店铺。
- 需要采集、选品和价格监控的运营团队。
- 为客户提供闲鱼代运营或 SaaS 服务的平台方。

### 产品特点

- 多账号集中管理，账号之间可独立配置。
- 平台账号级 AI 配置，同一客户下的闲鱼账号共享。
- 商品、订单、卡券、消息和日志统一管理。
- 自动续期、自动重连和定时任务降低维护成本。
- 套餐、配额、邀请码和角色权限支持平台化交付。
- 数据总览适合日常复盘和客户演示。
- 真实接口执行，结果可追踪、失败可定位。
