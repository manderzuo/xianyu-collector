# 闲鱼平台腾讯云中心化部署说明

## 一、部署目标

腾讯云服务器运行唯一的一套平台服务，包含：

- 前端页面
- 后端 API
- WebSocket 服务
- 定时任务服务
- MySQL
- Redis

客户电脑只访问腾讯云上的平台地址，不再各自初始化一套 MySQL 和 Redis。这样，客户在任意电脑提交的注册申请，管理员都可以在另一台电脑登录同一个平台地址后查看并审批。

## 二、注册审批流程

1. 用户在平台注册页面提交用户名、密码、邀请码和验证码。
2. 注册成功后，账号状态为“待审核”，不会直接进入系统。
3. 待审核账号尝试登录时，会提示“账号正在审核中，请等待管理员审批”。
4. 管理员进入“用户管理”，在待审核账号右侧选择“通过”或“拒绝”。
5. 通过后账号可以正常登录；拒绝后账号保持停用状态。

注册申请、账号状态、邀请码使用记录都保存在腾讯云的中心数据库中，因此不会因为更换管理员电脑而丢失或看不到申请。

## 三、服务器部署原则

生产环境建议只对公网开放 80/443 端口：

- MySQL 端口不要暴露到公网。
- Redis 端口不要暴露到公网。
- 后端和 WebSocket 尽量只允许前端反向代理或内网访问。
- 使用域名和 HTTPS，`CORS_ORIGINS` 配置为实际前端域名，不建议生产环境使用 `*`。
- JWT 密钥、数据库密码、Redis 密码必须使用服务器专用的强随机值。

服务器上的 Docker Compose 只部署一份。服务器更新代码或镜像后，重启这一份中心服务即可，所有客户端自动使用新版本。

## 四、客户端使用方式

### 中心化模式

客户端继续运行本地 Docker 保存闲鱼账号、Cookie、商品和任务数据；登录、注册申请、审批状态从腾讯云认证 API 获取。这样每台电脑的业务数据仍然隔离，账号审批状态又能跨电脑即时同步。

在客户端 `app/.env` 中配置：

```text
XIANYU_CLOUD_AUTH_URL=https://www.gemstory.cn
```

配置后，登录和注册请求会经过本机后端转发到腾讯云统一认证服务，管理员审批结果会在下一次登录或令牌校验时生效。

如果仍然需要使用安装包，安装包应仅用于启动客户端访问配置或部署辅助工具，不能让每台客户端各自生成独立的 MySQL/Redis 数据卷，否则每台电脑看到的用户和审批申请会不同。

### 单机模式

安装包保留单机部署能力，适合离线测试或客户要求数据完全保存在本机的场景。单机模式下，不同电脑之间的数据天然隔离，不能用于跨电脑审批注册申请。

## 五、上线前检查清单

- 腾讯云服务器已安装 Docker Engine 和 Docker Compose。
- 域名 DNS 已解析到服务器公网 IP。
- HTTPS 证书已配置。
- 服务器防火墙只放行 80/443，以及必要的 SSH 管理端口。
- MySQL 和 Redis 使用持久化卷，并已配置定期备份。
- 管理员账号可以登录用户管理页面。
- 新注册账号显示为“待审核”。
- 待审核账号无法登录。
- 管理员点击“通过”后，用户可以登录。
- 管理员点击“拒绝”后，用户无法登录。
- 从另一台电脑提交注册申请，管理员电脑可以看到同一条待审核记录。

## 六、当前还需要服务器侧执行的工作

本次代码已经支持中心化注册审批，但尚未直接登录腾讯云执行部署。正式上线还需要在服务器上完成：

1. 上传最新代码或构建最新镜像。
2. 配置生产环境变量。
3. 启动唯一的一套 Compose 服务。
4. 使用公网域名验证注册、审批和跨电脑登录流程。

执行服务器部署时，需要服务器公网 IP 或域名、SSH 登录方式，以及现有部署目录信息。不要把密码、私钥或 JWT 密钥提交到代码仓库。
