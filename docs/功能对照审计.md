## 扫码登录验收记录

已验证：

1. `POST /api/v1/qr-login/generate` 能访问闲鱼登录服务并返回 `data:image/png;base64,...`。
2. `GET /api/v1/qr-login/status/{session_id}` 能持续返回 `waiting`，后台日志能看到真实 `query.do` 轮询。
3. `POST /api/v1/qr-login/cancel/{session_id}` 能将会话置为 `cancelled`。
4. 前端 `/qr` 页面能显示真实二维码和轮询状态，不再打开无效的通用添加记录弹窗。
5. `/accounts` 列表已增加“详情”，可查看平台账号 ID、Cookie 脱敏摘要、连接状态以及关联内容数量。

尚需真实手机操作验证：用闲鱼 App 扫描当前二维码并确认后，检查闲鱼返回的登录令牌收口、Cookie 写入 `xr_accounts` / `xr_account_cookies`、账号连接服务交接和前端成功状态。自动化环境无法代替手机确认，因此本次不把“生成二维码”冒充成“扫码成功”。

## 外部执行边界

- 商品同步已实际调用登录态下的 `mtop.idle.web.xyh.item.list` 并保存商品卡片；卖家订单同步已实际调用 `mtop.taobao.idle.trade.merchant.sold.get`，平台权限不足时保留原始错误，不伪造空订单。
- 连接服务已接收扫码后的登录态并维护闲鱼 IM 长连接、心跳、重连和续期；自动化环境不能代替手机完成最终扫码确认。
- 卡券上游、SMTP、第三方支付回调和人脸供应商没有配置时，接口会返回明确的 `not_configured` / `waiting_for_connection`，不会伪造成功。卡券页面需要在部署环境填写 `CARD_DOCK_BASE_URL` 和 `EXTERNAL_API_KEY`。
