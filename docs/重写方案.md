# 闲鱼自动化系统 - 重写方案（干净仓库）

> 目标：在当前工作区独立重写，不直接复制历史仓库代码；平台链路按公开协议和当前业务需求重新实现。
> 原则：功能参考、代码重写；新仓库拥有独立品牌和配置，不包含历史署名、推广入口或远程控制体系。

## 0. 结论
- **不做“原样搬运+删作者名”**：原仓库 AGPL-3.0，直接搬运后删标识属于违反许可证与著作权管理信息（CMI）规定，发布即侵权。
- **正确做法 = 干净重写**：需求对齐原系统，但所有代码、文案、表结构、接口、前端页面全部重写；仅复用“通用想法”（如：多账号、关键词回复、自动发货、发布、定时任务、风控日志），不复用具体实现。
- 新仓库可自选许可证（如私有/ MIT），与原仓库完全隔离。

## 1. 新仓库定位
- 名称建议：`xianyu-rewrite` / 自定品牌名（待你确认）
- 形态：先本地隔离测试（Docker Compose），前端可随后上 Cloudflare Pages，后端可上 Railway/Render 临时托管（沿用刚才验证的 `deploy-cf-test` 链路）
- 对标功能（按优先级）：
  1. 账号管理（扫码登录、Cookie 维护、续期、状态）
  2. 消息与自动回复（关键词/图片/默认/商品专属 + AI 透传）
  3. 商品发布（素材库、地址库、单发/批量、发布日志）
  4. 订单与售后（拉单、自动评价、求小红花、超时检测）
  5. 采集与监控（Goofish 采集、货源、分销；参考咱们 `goofish-scraper` 能力）
  6. 通知与风控（风控日志、通知渠道）
  7. 定时任务中心（可视化配置、手动触发）

## 2. 技术选型（沿用已验证栈，做减法）
- 后端：Python 3.11 + FastAPI + SQLAlchemy 2.0 + asyncmy + Redis 7 + APScheduler
- 自动化：Playwright / Patchright（仅发布/验证场景需要；纯接口场景用 mtop 协议直连）
- 前端：React 18 + TypeScript + Vite + TailwindCSS + Zustand + React Router
- 基础设施：MySQL 8 + Redis 7 + Nginx（前端静态 + /api 代理）
- 部署：`docker-compose.yml` 单机一键起；`frontend/dist` 直出 Cloudflare Pages；后端 `functions/api/[[path]].js` 代理到后端公网

## 3. 架构（精简为 3 服务 + 2 基建，与刚才健康检查一致）
```
Browser -> CF Pages (dist) -> Functions /api,/static -> backend-web:8089
                                                    -> websocket:8090 (长连接、心跳、重连)
                                                    -> scheduler:8091 (20+ 定时循环)
                                                    -> mysql:3306 / redis:6379
```
- `backend-web`：业务 API、鉴权（JWT）、文件/素材、发布编排
- `websocket`：闲鱼长连接、消息收发、自动回复路由（含 AI 透传）
- `scheduler`：补发货、补评价、擦亮、拉单/拉商品、Token/Cookie 续期、监控等

## 6. 关键差异点（独立化实现）
